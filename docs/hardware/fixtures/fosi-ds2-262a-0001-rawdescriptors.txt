Fosi Audio DS2 (262a:0001) raw descriptors captured in the field via
Android UsbDeviceConnection.getRawDescriptors() (Flowy USB diagnostics,
two independent devices: HUAWEI OXF-AN10 / Android 10 and vivo V2454A /
Android 16 — byte-identical dumps). High-speed UAC2, async feedback.

Why this fixture matters — the interface-numbering trap:
  interface 0 = HID (volume buttons/controls)
  interface 1 = AudioControl (UAC2), clock source id=1 (bmControls 0x07)
  interface 2 = AudioStreaming, alts:
    alt1  2ch 16-bit subslot2  EP 0x03 maxPkt 200  ASYNC  fb 0x84/4B
    alt2  2ch 24-bit subslot3  EP 0x03 maxPkt 300  ASYNC  fb 0x84/4B
    alt3  2ch 32-bit subslot4  EP 0x03 maxPkt 400  ASYNC  fb 0x84/4B
    alt4  2ch 32-bit subslot4  EP 0x03 maxPkt 400  ASYNC  fb 0x84/4B
          (AS_GENERAL bmFormats 0x80000000 RAW_DATA — DSD alt)
  Feature Unit id=0x0A: master = Mute only, per-channel Volume (ch1/ch2).

Most DACs put AudioControl at interface 0 — the DS2 puts HID there.
Clock-entity class requests addressed with wIndex low byte = 0 land on
the HID interface and STALL: on this device SET_CUR(SAM_FREQ) "fails on
every clock source id", the DAC stays on its power-on 48 kHz default,
and 44.1k playback grinds (feedback demands 6.0 fpsi vs nominal 5.5125).
The rate RANGE request — the one code path that passed the parsed AC
interface number — succeeded on the same device in the same session.
wIndex must always carry layout.controlInterfaceId.

Second trap: the first alt setting with endpoints (alt1) has
wMaxPacketSize=200, but streaming runs on alt3 (400). Geometry taken
from "the first alt found" clamps every packet at 200 bytes, which
starves ≥176.4 kHz rates (192k peak packets need 208+ bytes).
